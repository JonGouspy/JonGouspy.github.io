A robot that turns on its own toward the brightest light source.

Context

The principle is simple: two light sensors on either side of the robot measure light intensity. If one side gets more light than the other, the motor turns to rebalance — and the robot ends up pointing at the source.

Behind that simplicity: analog acquisition, noise filtering, a dead zone to avoid oscillations, and bidirectional motor control.

Technical highlights

Acquisition

Each photoresistor forms a voltage divider; the voltage is read by the microcontroller's analog-to-digital converter.

Calibration

The two sensors never respond exactly the same: an offset measured at startup compensates for the difference.

Filtering

Moving average over several samples to smooth out noise (fluorescent lights, 50 Hz flicker).

Dead zone

Below a threshold, the motor stays still: the robot doesn't jitter once it's aligned.

Proportional control

Speed (PWM) depends on the error: fast rotation when the light is far off, slowing down as it gets aligned.

Power stage

An H-bridge isolates the microcontroller from the motor current and allows reversing the direction.

Code excerpt

C
#define DEADBAND 20

void loop(void) {
    int left  = read_avg(ADC_LEFT,  8);
    int right = read_avg(ADC_RIGHT, 8) + calib_offset;
    int err   = left - right;

    if (abs(err) < DEADBAND) {
        motor_stop();
    } else {
        int speed = clamp(abs(err) * KP, PWM_MIN, PWM_MAX);
        motor_set(err > 0 ? DIR_LEFT : DIR_RIGHT, speed);
    }
}

Key takeaways

  • Turning a simple idea into a physical system that actually works (noise, tolerances, mechanics).
  • Control basics: error, gain, dead zone, stability.
  • Cleanly separating control logic from the power stage.
