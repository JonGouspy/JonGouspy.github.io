Context

An MPU6050 provides 3-axis accelerations and angular rates. In theory, integrating acceleration twice gives you position. In practice, the slightest bias blows up: after a few seconds, the position drifts by several meters.

This project combines two techniques to make the estimate usable: the Madgwick filter to know the sensor's orientation, and ZUPT (Zero Velocity Update) correction to reset velocity to zero whenever the sensor is still.

Technical highlights

I²C driver

Communication with the MPU6050 through the ESP-IDF I²C API: range configuration (±g, °/s), burst register reads.

FreeRTOS tasks

A fixed-rate acquisition task and a processing task, exchanging data through a queue for regular sampling.

Madgwick filter

Gyro + accelerometer fusion via gradient descent on an orientation quaternion, tuned by the β parameter.

World frame

Acceleration is rotated into the Earth frame using the quaternion, then gravity is subtracted to keep only linear acceleration.

Stillness detection

Over a sliding window: acceleration norm close to g and near-zero rotation → the sensor is considered stationary.

ZUPT correction

At each stationary phase, velocity is forced to zero: accumulated error is cut off and position drift stays bounded.

Code excerpt

C
static bool is_stationary(const imu_sample_t *s)
{
    float a_norm = vec3_norm(s->acc);          // in g
    float w_norm = vec3_norm(s->gyro);         // in rad/s
    return fabsf(a_norm - 1.0f) < ACC_TH && w_norm < GYRO_TH;
}

void process(imu_sample_t *s, float dt)
{
    madgwick_update(&q, s->gyro, s->acc, BETA, dt);
    vec3 a_world = quat_rotate(q, s->acc);
    a_world.z -= 1.0f;                         // remove gravity

    if (window_all(is_stationary)) vel = VEC3_ZERO;   // ZUPT
    else vel = vec3_add(vel, vec3_scale(a_world, G * dt));

    pos = vec3_add(pos, vec3_scale(vel, dt));
}

Key takeaways

  • Correcting drift with prior knowledge (here: stationary phases).
