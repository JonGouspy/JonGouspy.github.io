Context

The goal: design from scratch a small console that runs Snake — schematic, PCB layout, soldering, then the game firmware.

The interesting constraint: driving many LEDs with very few pins. That's where charlieplexing comes in: it uses the high-impedance state of GPIOs to address n × (n − 1) LEDs with only n pins.

Technical highlights

Charlieplexing

To light an LED, one pin is driven high, another low, and all others are set as inputs (high impedance). With 9 pins: 9 × 8 = 72 addressable LEDs, enough for an 8 × 8 grid.

Scanning

Only one LED (or one row) is on at a time, but scanning is fast enough for persistence of vision to show a stable image.

Layout

Charlieplexing wiring is dense and counter-intuitive: LED placement and trace routing required particular care.

Inputs

Direction buttons with software debouncing, read between refresh cycles.

Game logic

Snake stored in a circular buffer, apple generation, collision detection and progressive speed-up.

Power

Sizing of current-limiting resistors and power supply for even brightness.

// Turn on the LED between pin `hi` (anode) and `lo` (cathode)
static void led_on(uint8_t hi, uint8_t lo)
{
    PIN_DDR  = 0;                    // all pins high-impedance
    PIN_PORT = 0;
    PIN_DDR  = (1 << hi) | (1 << lo);// only hi and lo become outputs
    PIN_PORT = (1 << hi);            // hi = 1, lo = 0 -> current through LED
}

ISR(TIMER_vect)                       // display refresh
{
    static uint8_t i = 0;
    if (framebuffer[i]) led_on(led_map[i].hi, led_map[i].lo);
    else                PIN_DDR = 0;
    i = (i + 1) % NB_LEDS;
}
