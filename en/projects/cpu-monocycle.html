Context

A single-cycle processor executes each whole instruction — fetch, decode, execute, memory access, write-back — in one clock cycle. It's the simplest architecture to reason about, and the foundation for understanding pipelining later on.

The project consists of describing each datapath block in VHDL, wiring them together with a control unit, then validating everything in simulation on real programs.

Technical highlights

ALU

Arithmetic and logic operations, with flags (N, Z, C, V) used for conditional branches.

Register file

Two asynchronous read ports, one write port synchronous on the clock edge.

Control unit

Decodes the opcode into control signals: mux selection, register / memory write, ALU operation.

Memories

Instruction memory initialized with the program, separate data memory (Harvard architecture).

PC logic

Increment, relative branches and jumps, selected by a multiplexer based on the flags.

Verification

One testbench per entity, then a global testbench that runs a program and checks the registers at the end of execution.

Code excerpt

VHDL
entity alu is
  port (
    op     : in  std_logic_vector(1 downto 0);
    a, b   : in  std_logic_vector(31 downto 0);
    s      : out std_logic_vector(31 downto 0);
    n_flag : out std_logic
  );
end entity;

architecture rtl of alu is
  signal res : signed(31 downto 0);
begin
  with op select res <=
    signed(a) + signed(b) when "00",
    signed(b)             when "01",
    signed(a) - signed(b) when "10",
    signed(a)             when others;

  s      <= std_logic_vector(res);
  n_flag <= res(31);
end architecture;

Key takeaways

  • Thinking in hardware: concurrency, signals, timing, rather than a sequence of instructions.
  • Understanding concretely how an instruction turns into electrical signals.
  • The importance of simulation-based verification before any synthesis.
