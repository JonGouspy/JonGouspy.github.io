Contexte

Un processeur monocycle exécute chaque instruction entière — lecture, décodage, exécution, accès mémoire, écriture — en un seul cycle d'horloge. C'est l'architecture la plus simple à raisonner, et la base pour comprendre ensuite le pipeline.

Le projet consiste à décrire chaque bloc du chemin de données en VHDL, à les assembler avec une unité de contrôle, puis à valider le tout en simulation sur de vrais programmes.

Points techniques

ALU

Opérations arithmétiques et logiques, drapeaux (N, Z, C, V) utilisés pour les branchements conditionnels.

Banc de registres

Deux ports de lecture asynchrones, un port d'écriture synchrone sur front d'horloge.

Unité de contrôle

Décodage de l'opcode en signaux de commande : sélection des multiplexeurs, écriture registre / mémoire, opération ALU.

Mémoires

Mémoire d'instructions initialisée avec le programme, mémoire de données séparée (architecture Harvard).

Gestion du PC

Incrément, branchements relatifs et sauts, sélectionnés par multiplexeur selon les drapeaux.

Vérification

Un testbench par entité, puis un testbench global exécutant un programme et vérifiant les registres en fin d'exécution.

Extrait de code

VHDL
entity alu is
  port (
    op     : in  std_logic_vector(1 downto 0);
    a, b   : in  std_logic_vector(31 downto 0);
    s      : out std_logic_vector(31 downto 0);
    n_flag : out std_logic
  );
end entity;

architecture rtl of alu is
  signal res : signed(31 downto 0);
begin
  with op select res <=
    signed(a) + signed(b) when "00",
    signed(b)             when "01",
    signed(a) - signed(b) when "10",
    signed(a)             when others;

  s      <= std_logic_vector(res);
  n_flag <= res(31);
end architecture;

Ce que j'en retiens

  • Penser en matériel : concurrence, signaux, timing, plutôt qu'en séquence d'instructions.
  • Comprendre concrètement comment une instruction devient des signaux électriques.
  • L'importance de la vérification par simulation avant toute synthèse.
