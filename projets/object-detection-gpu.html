Contexte

Sur une vidéo filmée par une caméra fixe, tout ce qui ne fait pas partie du décor est un objet d'intérêt. L'idée : apprendre un modèle du fond (background), puis isoler pour chaque image les pixels qui s'en écartent.

Le calcul étant indépendant pour chaque pixel, il se prête parfaitement au GPU. Le projet consiste à écrire une version CPU de référence, puis à la porter en kernels CUDA et à mesurer le gain.

Points techniques

Modèle de fond

Fond estimé et mis à jour au fil de la vidéo (moyenne glissante), pour s'adapter aux changements lents d'éclairage.

Masque de mouvement

Distance entre l'image courante et le fond, puis seuillage avec hystérésis : un seuil haut pour amorcer, un seuil bas pour propager.

Morphologie

Érosion puis dilatation pour supprimer le bruit isolé et reboucher les trous dans les objets.

Un thread par pixel

Chaque kernel associe un thread à un pixel ; grilles 2D, accès mémoire coalescés.

Mémoire partagée

Les opérations à voisinage (morphologie) chargent une tuile + son halo en shared memory pour éviter les relectures en mémoire globale.

Benchmark

Comparaison CPU vs GPU et profilage (Nsight) pour identifier les kernels limités par la bande passante.

Extrait de code

__global__ void diff_threshold(const uchar3* frame, const float3* bg,
                               uint8_t* mask, int w, int h, float th)
{
    int x = blockIdx.x * blockDim.x + threadIdx.x;
    int y = blockIdx.y * blockDim.y + threadIdx.y;
    if (x >= w || y >= h) return;

    int i = y * w + x;
    float3 d = make_float3(frame[i].x - bg[i].x,
                           frame[i].y - bg[i].y,
                           frame[i].z - bg[i].z);
    float dist = sqrtf(d.x*d.x + d.y*d.y + d.z*d.z);
    mask[i] = dist > th ? 255 : 0;
}

Ce que j'en retiens

  • Penser un algorithme en termes de parallélisme massif.
  • L'impact énorme des accès mémoire sur les performances GPU.
  • Mesurer avant d'optimiser : profiler, comparer, itérer.
