Contexte

Un MPU6050 fournit des accélérations et des vitesses angulaires sur 3 axes. En théorie, il suffit d'intégrer deux fois l'accélération pour obtenir la position. En pratique, le moindre biais explose : après quelques secondes la position dérive de plusieurs mètres.

Ce projet combine deux techniques pour rendre l'estimation exploitable : le filtre de Madgwick pour connaître l'orientation du capteur, et la correction ZUPT (Zero Velocity Update) pour remettre la vitesse à zéro dès que le capteur est immobile.

Points techniques

Driver I²C

Communication avec le MPU6050 via l'API I²C d'ESP-IDF : configuration des plages (±g, °/s), lecture en rafale des registres.

Tâches FreeRTOS

Une tâche d'acquisition à fréquence fixe, une tâche de traitement ; échange par file (queue) pour un échantillonnage régulier.

Filtre de Madgwick

Fusion gyro + accéléromètre par descente de gradient sur un quaternion d'orientation, réglée par le paramètre β.

Repère monde

L'accélération est tournée dans le repère terrestre grâce au quaternion, puis la gravité est soustraite pour garder l'accélération linéaire.

Détection d'immobilité

Sur une fenêtre glissante : norme de l'accélération proche de g et rotation quasi nulle → le capteur est considéré à l'arrêt.

Correction ZUPT

À chaque phase d'arrêt, la vitesse est forcée à zéro : l'erreur accumulée est coupée, la dérive de position reste bornée.

Extrait de code

C
static bool is_stationary(const imu_sample_t *s)
{
    float a_norm = vec3_norm(s->acc);          // en g
    float w_norm = vec3_norm(s->gyro);         // en rad/s
    return fabsf(a_norm - 1.0f) < ACC_TH && w_norm < GYRO_TH;
}

void process(imu_sample_t *s, float dt)
{
    madgwick_update(&q, s->gyro, s->acc, BETA, dt);
    vec3 a_world = quat_rotate(q, s->acc);
    a_world.z -= 1.0f;                         // retire la gravité

    if (window_all(is_stationary)) vel = VEC3_ZERO;   // ZUPT
    else vel = vec3_add(vel, vec3_scale(a_world, G * dt));

    pos = vec3_add(pos, vec3_scale(vel, dt));
}
