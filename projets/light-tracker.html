Light Tracker

Un robot qui s'oriente tout seul vers la source de lumière la plus intense.

Contexte

Le principe est simple : deux capteurs de lumière placés de part et d'autre du robot mesurent l'intensité lumineuse. Si un côté reçoit plus de lumière que l'autre, le moteur tourne pour rééquilibrer — le robot finit pointé vers la source.

Derrière cette simplicité : acquisition analogique, filtrage du bruit, zone morte pour éviter les oscillations et pilotage d'un moteur dans les deux sens.

Points techniques

Acquisition

Chaque photorésistance forme un pont diviseur ; la tension est lue par le convertisseur analogique-numérique du microcontrôleur.

Calibration

Les deux capteurs n'ont jamais exactement la même réponse : un offset mesuré au démarrage compense l'écart.

Filtrage

Moyenne glissante sur plusieurs échantillons pour lisser le bruit (néons, scintillement 50 Hz).

Zone morte

En dessous d'un seuil d'écart, le moteur reste à l'arrêt : le robot ne « tremble » pas une fois aligné.

Commande proportionnelle

La vitesse (PWM) dépend de l'écart : rotation rapide quand la lumière est loin, ralentissement à l'approche.

Puissance

Un pont en H isole le microcontrôleur du courant moteur et permet d'inverser le sens de rotation.

Extrait de code

C
#define DEADBAND 20

void loop(void) {
    int left  = read_avg(ADC_LEFT,  8);
    int right = read_avg(ADC_RIGHT, 8) + calib_offset;
    int err   = left - right;

    if (abs(err) < DEADBAND) {
        motor_stop();
    } else {
        int speed = clamp(abs(err) * KP, PWM_MIN, PWM_MAX);
        motor_set(err > 0 ? DIR_LEFT : DIR_RIGHT, speed);
    }
}

Ce que j'en retiens

  • Passer d'une idée simple à un système physique qui marche vraiment (bruit, tolérances, mécanique).
  • Les bases de l'asservissement : erreur, gain, zone morte, stabilité.
  • Séparer proprement la logique de commande et l'étage de puissance.
