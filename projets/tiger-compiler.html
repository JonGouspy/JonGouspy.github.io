Contexte

Tiger est un petit langage impératif typé, issu du livre Modern Compiler Implementation d'Andrew Appel. Il possède des types structurés (records, tableaux), des fonctions imbriquées, des portées lexicales et une gestion explicite de let … in … end.

L'objectif : partir d'un fichier source .tig et produire du code exécutable, en traversant toutes les étapes d'un vrai compilateur — de l'analyse lexicale jusqu'à l'allocation de registres.

Points techniques

Analyse lexicale & syntaxique

Scanner Flex et grammaire Bison, avec gestion des conflits, des priorités d'opérateurs et des messages d'erreur localisés (ligne / colonne).

AST & visiteurs

Arbre syntaxique abstrait en C++ parcouru via le design pattern Visitor : pretty-printer, binder, type-checker et traducteur partagent la même hiérarchie.

Liaison des noms

Résolution des identifiants avec tables de symboles à portées imbriquées, détection des variables qui « s'échappent » vers des fonctions internes.

Vérification de types

Typage des expressions, des records récursifs et des tableaux ; erreurs sémantiques claires plutôt qu'un crash.

Représentation intermédiaire

Traduction en arbre IR, linéarisation et canonisation des blocs de base avant la génération de code.

Back-end

Sélection d'instructions par tuilage de motifs, analyse de vivacité et allocation de registres par coloration de graphe.

Extrait de code

let
  type intlist = { head: int, tail: intlist }
  function sum(l: intlist): int =
    if l = nil then 0
    else l.head + sum(l.tail)
  var l := intlist { head = 1,
           tail = intlist { head = 2, tail = nil } }
in
  print_int(sum(l))
end

Ce que j'en retiens

  • Comprendre ce qui se passe réellement entre le code source et le binaire.
  • Concevoir une grosse base de code C++ modulaire et testable (suites de tests par étape).
  • Travailler en équipe sur un projet long avec revues de code et intégration continue.
