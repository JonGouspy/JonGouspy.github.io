Contexte

Le but : concevoir de A à Z une petite console qui fait tourner Snake — schéma électronique, routage du PCB, soudure, puis firmware du jeu.

La contrainte intéressante : piloter beaucoup de LEDs avec très peu de broches. C'est là qu'intervient le charlieplexing, qui exploite l'état haute impédance des GPIO pour adresser n × (n − 1) LEDs avec seulement n broches.

Points techniques

Charlieplexing

Pour allumer une LED, une broche est mise à 1, une autre à 0, toutes les autres en entrée (haute impédance). Avec 9 broches : 9 × 8 = 72 LEDs adressables, assez pour une grille 8 × 8.

Balayage

Une seule LED (ou une ligne) est allumée à la fois, mais le balayage est assez rapide pour que la persistance rétinienne affiche une image stable.

Routage

Le câblage du charlieplexing est dense et peu intuitif : le placement des LEDs et des pistes a demandé un soin particulier.

Entrées

Boutons de direction avec anti-rebond logiciel, lus entre deux cycles de rafraîchissement.

Logique de jeu

Serpent stocké dans un buffer circulaire, génération de la pomme, détection des collisions et accélération progressive.

Alimentation

Dimensionnement des résistances de limitation et de l'alimentation pour une luminosité homogène.

Extrait de code

C
// Allume la LED reliée entre la broche `hi` (anode) et `lo` (cathode)
static void led_on(uint8_t hi, uint8_t lo)
{
    PIN_DDR  = 0;                    // toutes les broches en haute impédance
    PIN_PORT = 0;
    PIN_DDR  = (1 << hi) | (1 << lo);// seules hi et lo deviennent des sorties
    PIN_PORT = (1 << hi);            // hi = 1, lo = 0 -> courant dans la LED
}

ISR(TIMER_vect)                       // rafraîchissement de l'écran
{
    static uint8_t i = 0;
    if (framebuffer[i]) led_on(led_map[i].hi, led_map[i].lo);
    else                PIN_DDR = 0;
    i = (i + 1) % NB_LEDS;
}
